# 交付检查

依据 proto-gen 的结构与原型说明机制，按本项目低保真和走查目标重写。按实际工作范围检查，不要求额外插件或固定评审 Agent。

- PRD 是用户八章规范或用户现有文档；未知联系人、指标、业务规则标待确认。没有凭空加入功能。
- PRD 文首状态与实际一致：正式原型对应「已审查通过」；决策记录无遗留「待决策」项，或剩余项已明确汇报给用户。需求性修改后状态已回退并重新审查。
- 把完整 PRD 与 requirements、groups 对照：核心路径、重要分支和明示状态都有独立屏幕；脚本只能检查已提取需求是否映射，不能证明没有漏提取。
- `index.html` 一个总索引，说明各分组内容与入口；屏幕按使用顺序在所属分组页面平铺，拆分只到流程分组、不把单屏拆成独立页面。每屏名称、状态、流程位置（第几步、上一屏 / 下一屏）、进入 / 复现方式、操作与跳转明确，跳转可点击（跨分组带页面文件名）或明确标待确认 / 终点。
- 原型只用中性灰加不超过 5 种低饱和功能色（雾蓝 / 灰绿 / 灰琥珀 / 砖红，语义见 wireframe-guide 配色规范）和基础框线，颜色仅表达功能语义，不做视觉美化；图片为占位块。信息层级用 heading 1–3 级区分；核心文案写实；每屏最多一个主操作且样式突出；组件没有溢出、重叠和无故裁剪。小屏可堆叠，大屏截图与原型并排。
- 每屏「原型说明」面板独立且与本屏一一对应：summary 说清任务与进入条件，layout 说清布局分区职责，组件 note 说清展示、操作、结果与规则（编号与线框一一对应、可联动），logic 说清条件展示与边界；说明不照抄 PRD，PRD 原文折叠在「PRD 依据」中可追溯。实际界面和设计原意不一致时明确标原逻辑、依据和修改点，不把截图照描成设计。
- 截图标注用红色编号矩形 / 圆点 / 箭头覆盖层，不修改原图；编号与说明一一对应、箭头指向清晰不被裁切；标注聚焦关键差异；标注红不出现在线框内。
- live 走查在用户确认计划后才执行；更改 PRD / 计划后旧确认失效。截图来源、实际状态、复现步骤和文件真实可核查；缺失或阻塞明确可见。
- 本轮页面反馈可输入问题 / 建议，快捷标记可选择和取消；每组有流程反馈；刷新可以恢复；保存失败有提示；Markdown / JSON 都可以导出。同轮各页面共享本地保存，任一页面导出的 JSON 都包含全部分组反馈。
- 下一轮保留历史原话（包括已删除页面），本轮输入为空；跨项目反馈或错误轮次被拒绝；改动 / 新增 / 不变标记与实际输入一致。
- 生成的每个 HTML 都离线可打开：CSS、JS、截图内嵌，页面之间用相对链接，无 CDN、远程图片、外部字体或运行时接口请求。浏览器检查没有脚本错误。
- 生成或修改工具实现时运行 `npm test`；有浏览器运行时变更时执行 README 的浏览器验收。只运行与变更相关的检查，不反复跑无新增价值的测试。
