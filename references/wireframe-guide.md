# 低保真原型方案

目标是让读者从页面与简短说明理解功能、操作结果、数据变化和异常处理。参考真实竞品截图中的结构与交互做法；设计依据仍是本次 PRD。

## 层级与画面

- **功能流程**：按用户任务分组，每组一页 HTML；索引说明分组内容并链接。
- **页面状态**：一屏一个明确状态。先展示主路径，再放重要分支；布局或交互无明显差异的状态在说明中交代，避免重复整屏。
- **原型与说明**：线框突出关键内容和操作，旁注解释不自明的规则。PRD 原文、参考截图和历史信息折叠或链接查看。

线框用 `heading` 1–3 级、`section` / `columns`、留白与框线表达模块关系。核心文案写实，图片用占位块。按钮是否禁用由产品规则决定，不因原型没有实现业务而置灰。每个 action 必须画出按钮位置，设计新方案时每屏通常保留一个主操作；竞品复原按实页保留同级重复操作，不为迁就规范改变原布局；不添加品牌装饰、字体依赖或高保真视觉。示例业务数据注明“示意”。

沿用中性灰和已有四种低饱和功能色：雾蓝＝操作／强调，灰绿＝通过，灰琥珀＝待确认／更新，砖红＝异常／标注。颜色配文字，不添加无关视觉规范。

画布中只保留产品真实内容，产品本身的校验／错误提示照常绘制。画布外展示终端尺寸、页面状态、组件说明与编号、来源、操作结果、跳转和反馈；不在按钮旁堆设计说明，也不额外添加箭头或编号挤占布局。

## PC 与移动端

线框本身分两种样式，保持低保真。没有明确限制时 PC 与移动端都绘制，不预设终端优先级；两端分配独立 screen id，可在同一流程分组内相邻呈现，共用 PRD 需求编号。

- PC：先定位顶部导航、侧栏与主内容，按目标窗口组织多栏、表格和行内操作。侧栏等需要准确宽度时用组件 `width`，其余区域用 columns 的剩余空间。
- 移动端：单独安排顶部导航、单列信息、触控操作和底部操作／导航。需要同排元素时显式用 columns；不要继承 PC 的多栏布局。触控主按钮使用移动端样式。
- `frame` 是产品内容视口，优先沿用真实截图的内容尺寸或用户指定设备；缺少依据时使用 PC 1280×800、移动端 390×844，并说明这是基准尺寸。不要把浏览器工具栏算进产品画布，也不凭空添加手机外壳。
- 顶层组件 `region: header / body / footer` 表示固定顶部、可滚动内容、固定底部，未标记时在 body 顺序排列。只有产品需要固定区域时才使用；普通底部内容仍留在 body。
- 预览缩放整张画布，保持内部尺寸、对齐和相对位置；预览窗口变窄只改变文档排版，不能把 PC 画布自动重排成移动布局。超长内容在画布内容区滚动，关键异常或弹层需单独状态展示。
- 按参考核对导航位置、栏宽、对齐、模块顺序、按钮归属、固定区与滚动边界；纯文本无法确定的位置作为布局建议说明，不承诺没有尺寸依据的像素级复刻。

## 写清必要说明

| 内容 | 字段与写法 |
| --- | --- |
| 本屏任务与进入条件 | `summary` 一句话；`reproduce` 列必要进入步骤 |
| 模块职责 | `layout`，仅在画面不足以说明时写；不描述像素或重复标题 |
| 关键组件行为 | `blocks[].note`，写展示来源、触发方式、反馈与校验；自明标题、普通文本省略 |
| 业务规则 | `logic`，用“若…则…”交代条件、权限及边界；未决规则进 `pending` 并引用 Q 编号 |
| 数据流向 | `dataFlow`，交代数据来源、触发更新、保存／传递结果和影响页面；用产品对象描述，不猜接口或存储实现 |
| 用户操作 | `actions`：按钮文案、操作后结果、去向；由 action 组件画出位置 |
| 自动流转 | `transitions`：条件 → 目标状态，例如保存成功／失败，和用户点击区分 |

说明按需出现，同一规则只在最合适的位置写一次。组件 note 在画布外编号并与线框悬停联动，不为凑齐模块给每个元素加长说明。

例如已确认的保存流程可写：

- 数据：用户输入标题 → 必填校验 → 保存资料；成功后列表更新，失败不新增记录并保留输入。
- 用户操作：点击保存 → 进入提交中。
- 自动流转：提交成功 → 列表；提交失败 → 失败提示，允许重试。

例子只示范写法，不是默认业务要求。PRD 没确定的失败处理必须先给问题和选项。

## 正向与异常

检查核心任务是否能完成、操作后是否有明确反馈、相关异常能否恢复。空数据、加载、失败、权限或重复提交只在与功能相关时展开；不能套一组通用状态自动增加需求。

真实业务流转由 `actions` / `transitions` 表达。“上一屏／下一屏”只是方案阅读导航，不代表成功路径或状态流转。目标明确但停留本屏／流程结束用 `null`，未知去向用“待确认”，不要用 `null` 隐藏缺失设计。

## 旧功能与参考

旧页面截图与竞品截图在索引的“设计参考”集中呈现，并关联到受影响页面。用户明确说明的旧页面截图（`existing`）在图上用 `changes` 标记变更点、图下补充原逻辑与新逻辑；明确说明的参考图（`competitor`）只作页面参考，不标变更点。只写实际观察到的旧逻辑、具体修改点及来源；未观察到的行为标待确认。`annotations` 可按组件补充旧逻辑和修改点，无需为每个页面创建对照走查。

HTML 中的标记、问题和建议用于方案迭代，原话保留。业务建议按 SKILL 的反馈规则先写回 PRD，表达问题直接改原型。

## 把模糊说明改成可判定行为

只补影响实现与决策的信息，使用现有 note / logic / dataFlow / actions / transitions，不新增长表模板。按需写“前置条件 → 控件与触发 → 可见变化 → 数据影响 → 去向／恢复”；没有证据或 PRD 依据的环节标未验证／待决策，不为填满链条编行为。

| 模糊表述 | 精确写法示例（须有本次依据） |
| --- | --- |
| 切换视图 | 分镜板顶部点击「镜头表」→ URL 保持不变；内容区换成镜头表，当前集不变；0 条记录时显示「暂无数据」，可点击「分镜板」返回。视图切换不等于新增或删除分镜。 |
| 清空选择 | 导出弹层点击「清空」→ 本次剧集选择清空，按钮变「全选」；导出格式保持 PDF；不删除剧集。若尚未提交，导出按钮是否拦截空选择写未验证。 |
| 自动保存 | 写明实际观察到的触发、保存中／成功／失败提示位置及刷新后的结果；只看到编辑框不能写成自动保存。未知防抖时间不编造数值。 |
| 保存失败可重试 | 若 PRD 已确认：失败提示位于表单上方；保留字段输入，恢复保存按钮；再次提交仍使用当前输入。说明是否已有记录及重复提交处理，不能只写“异常提示”。 |

行为改变但 URL 不变仍可能是独立页面状态。交互链接从实际控件开始；单击只打开弹层时，不能越过配置步骤直连成功结果。原型中的跳转用于讲清行为，不声称执行真实保存、导出或生成。

## 已调研的表达案例

下列仅借鉴表达方法，不复制案例业务规则或虚构指标；按本项目要求，所有规格注释放在画布外。

- [Balsamiq · Feature Spec / PRD Layout](https://balsamiq.com/examples/internal-tools/feature-spec-prd-layout/)：官方展示的虚构产品 AI 示例，以相邻说明和线框状态相互引用；适合保留需求到画面的一一对应，不照搬其完整章节、数字或视觉装饰。
- [Balsamiq · Wireframe annotations](https://balsamiq.com/blog/wireframe-annotations/)：说明补足条件、功能与导航，保持短且不遮挡界面；自明组件无须逐一注释。
- [NN/g · Wireflows](https://www.nngroup.com/articles/wireflows/)：低保真画面结合流转，表现同页操作引起的状态变化；本项目将流转说明置于画布外，由画布中的实际按钮链接目标状态。
- [GOV.UK · Check answers](https://design-system.service.gov.uk/patterns/check-answers/)：修改已有答案时保留已有值，明确修改后返回确认页的路径；借鉴返回与依赖问题的说明精度，不默认所有产品都需要确认页。
- [GOV.UK · Validation](https://design-system.service.gov.uk/patterns/validation/)：字段附近的错误与页面错误摘要配合，保留输入便于恢复；区分校验错误、资格限制与服务故障。按实际需求采用，不套通用异常页面。
