# 精简功能 PRD

默认中文、短句、产品语言，输出 `PRD-<product>.md`。已有 PRD 按用户范围修改，保留有效内容；不为套模板重写整篇。历史八章来源仅保留作来源记录，默认不采用。

## 状态与审查

标题下一行只写一个当前状态，例如 `状态：草稿`、`状态：待决策` 或 `状态：已审查通过（YYYY-MM-DD）`。

- 草稿：补全中或发生业务变化。
- 待决策：业务、流程或验收仍有影响当前方案的未决项。
- 已审查通过：用户明确批准当前版本；保留本版本的通过记录，不要求每次对话重新批准。

用户回答问题后补正文并标记该问题已决策，不自动批准整份文档。业务变化撤销受影响版本的通过状态，待重新审查；无业务含义变化的文字修正不撤销。只有用户要求预览时才可据草稿绘图，HTML 明示仅供讨论。用户批准时仍有影响范围或核心流程的未决项，指出具体冲突并请其决策或移出本次范围，不能自行选答案。

## 默认内容

按需求规模使用以下五部分，不补空洞章节：

1. **背景与目标**：解决谁的什么问题、希望达到什么结果、本次范围。已知指标可写，未知数值不编造；不强制联系人、市场分析、OKR 或排期。
2. **功能与规则**：按功能模块写需求，分配稳定编号。写触发条件、展示／校验规则、操作结果及必要边界。旧功能用「旧逻辑｜新逻辑｜影响范围」表，只列变化与理解所需的上下文；旧逻辑注明用户描述或截图来源。
3. **流程与状态**：按用户路径说明进入条件、用户操作、数据变化、目标页面／状态和相关异常恢复方式。可用表格或短箭头链；数据用产品对象描述，例如「输入标题 → 校验 → 保存资料 → 列表刷新」，不猜接口名和数据库表。
4. **验收要点**：核心正向结果和重要异常行为，写成「在…条件下，执行…，应…」。避免与功能说明逐字重复。
5. **待决策**：只收集影响范围、行为或验收的未知项；无需用户决定的排版与表述自行处理。无未决项时写一句“无”即可。

只有会影响本功能的加载、空数据、失败、权限、重复提交、恢复等状态才纳入。不机械列全套异常，也不因用户未提及而漏掉显著流程缺口：给选项确认后写回规则。小差异可在同一页说明，交互／布局明显变化才拆独立页面状态。

## 决策记录

每条用稳定 Q 编号，在相关正文处引用该编号，集中列出待决题：

```markdown
- **Q1 · 待决策：保存失败后如何处理输入？**
  - 影响：决定失败提示与重试路径。
  - A：保留输入，允许重试（建议，避免重复填写）。
  - B：退出表单，返回列表（流程短，但输入丢失）。
  - 用户决定：待选择。
```

默认 2–3 个互斥、可执行选项，各附一句影响；建议必须说明理由，用户可给自定义答案。问题按影响大小集中提出，不逐项挤牙膏；不把未知联系人或无关排期变成阻塞项。等待时继续完成独立内容。

答案到达后，同时更新相关规则、流程和验收，记录「已决策、用户答案、日期」。已决策项收在本节末尾折叠保留，不挤占当前问题列表。部分回答只消除对应问题；与既有决定冲突时指出冲突并给选项，不自行折中。用户说“按建议都改”时可采用明确对应的建议，但仍需其明确审查通过才定稿。
