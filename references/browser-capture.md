# 旧页面观察与竞品截图参考

截图用于理解旧功能和支持原型设计。优先用会话中可用的浏览器或检索工具；这条工作路径不要求 `plan` / `approve`，不运行产品走查。用户已经授权访问或调研的范围直接执行，缺少网址、登录条件或关键业务决策时再问具体问题。

## 旧功能

阅读用户提供的旧／新逻辑；有页面地址时实际打开相关页面、查看必要交互并截图，有上传截图时先查看图片。记录页面、可见状态和来源，把观察事实与用户补充的行为区分。单张截图不能证明点击结果、校验时机或数据持久化，未观察到且用户未说明的行为进 PRD 决策项。只研究与改动相关部分。

## 竞品参考

- 优先用户指定竞品；未指定时根据同类任务选择少量直接相关页面，通常 1–3 个产品。先找能帮助当前布局、关键交互或异常处理的真实证据，避免泛行业分析。
- 优先实际页面或官方帮助文档内的界面截图，必要时用可靠公开页面；记录准确页面 URL、来源、采集日期和可见状态。只找到文字不算完成截图参考。
- 实际查看每张采用的截图，记录一句观察和一句「本方案如何借鉴／为何适用」。由截图推断的行为标成推断，不把行业惯例当用户业务规则。参考优秀方案的模块层级、信息密度、主次操作和状态表达，不照搬品牌视觉或整套功能。
- 用户已提供合适截图可复用；需求未变时不重复调研。登录受限或工具不可用时寻找官方公开截图，仍无证据则如实说明具体缺口，继续其他工作，不伪造图片或出处。
- 使用浏览器时遵循该工具的截图保存方式。图片只支持本地 PNG / JPEG / WebP；截图原图保留，不能用 AI 生成图片替代真实证据。

## 写入原型

将采用的截图保存到产物目录的 `references/`，每张保留明确来源；为图片计算 SHA256，写入 flow 顶层 `references`，格式见 [flow-format.md](flow-format.md)。旧页面用 `existing`，竞品用 `competitor`。按 `screens` 关联实际应用的页面状态。

HTML 索引集中展示参考图、观察和应用说明，每屏链接到相关参考。不把竞品截图塞进低保真业务画面；原型仍以 PRD 为依据。新一轮复用有效参考，只有来源过时或设计问题变化时补充。

历史 `review` 清单的浏览器 CLI 仍保留兼容，依然有原计划确认约束；不用于上述日常设计路径，也不把确认记录虚构成用户同意。
