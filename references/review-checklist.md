# 产物自检

只检查本次生成或修改的内容，不要求用户走查，不输出额外检查报告。

- PRD 精简且完整：背景目标、功能规则、流程状态、验收和待决策可定位。无虚构业务、指标、排期或已批准记录；用户答案已同步正文。
- 正式方案对应用户已审查通过的 PRD；草稿预览是用户要求且明确标注。旧 HTML 的版本与当前 PRD 区分。
- 原型覆盖核心路径、重要分支及相关异常恢复；页面操作和自动流转指向正确目标。脚本的编号／引用校验不能替代对完整 PRD 的语义核对。
- PC 与移动端分别布局并注明终端和画布尺寸；核对侧栏／导航／内容／底部区的位置、栏宽与对齐，缩放预览后内部布局不变，滚动内容不遮挡固定操作区。
- 层级为功能流程、页面状态、原型与说明；主次操作清晰。说明交代关键逻辑、交互、数据流向和状态变化，自明组件不堆旁注，无内容的模块不展示。
- 采用的竞品截图实际看过，有可核查来源、观察与具体借鉴点；旧逻辑的事实与推断分开，缺失参考如实交代。截图不自动带来新需求。
- 画布内仅有产品内容，设计说明／编号／状态元信息／来源／反馈均在外部；旁注不会挤占组件位置。
- HTML 索引与分组页可离线打开，相对跳转有效；文字／图片无重叠和异常裁切，小屏可阅读。参考截图和 PRD 原文按需展开，页面不加载外部资源。
- 页面标记、问题、建议可编辑与导出；历史原话保留。修改前保护相关旧反馈，不能将旧版本反馈静默覆盖到新版本。
- 修改工具实现后运行 `npm test`；修改渲染或交互后用实际生成的 HTML 检查相关表现。无代码变化不为文案增设测试或完整回归流程。
